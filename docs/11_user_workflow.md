# End-to-End User Workflow

## Local animation extension

### Corrected stage sequence and project controls

- Choose target length in **seconds** (1-600), not whole minutes. This remains a planning goal: complete narration may extend it; scene durations are editable in seconds.
- On **Plan**, review and approve **Automatic stage generation** once. The bounded quote includes all possible missing artwork and sequential GPU time. Default source is **Local generated motion**; still-image-only rendering must be selected explicitly. Narration/speech and final export keep separate estimate approvals.
- Generate planning, then continue to **Story**, not Scenes. Save/approve the story and continue to **Characters**: all missing portraits generate automatically. Preview/approve each, or explicitly regenerate individual results. Continue to **Scenes** after character approval: all missing scene images generate automatically. Supplied/completed assets are reused.
- After narration/audio/timeline review, enter **Render**: all missing local clips generate sequentially under the approved budget. Review/approve every clip before final export. Missing/stale/unapproved clips block local-animation export; it never silently falls back to still images. Each SVD clip still contains only two seconds of generated motion, followed by a final-frame hold for longer scenes.
- Reopening a stage attaches to its persisted progress. Failed batches stop and require an explicit **Retry missing assets** action; completed work is retained, not regenerated.
- **Plan → Edit original prompt / restart project** allows prompt, second-based target and limits to change. Confirmation clears all story, character/scene assets, imports, narration, animation clips and videos, returns to Plan, and preserves recorded spending. Nothing regenerates before new estimate approval.
- **Dashboard → Delete project** removes the entire project and its media after confirmation. **Your video → Delete exported videos** removes all exports/checkpoints only, preserving production assets for a new export. Both actions are blocked during running work.
- **Your video** reports whether actual model-generated clips were used, how many, and their generated-motion seconds. A legacy still-image export is identified honestly; updating the application does not change an already-rendered video.

approve a local generation estimate, wait for the GPU job, preview its clip, then
approve it for rendering. Declining/deselecting retains still-image effects.
The per-scene control remains available for explicit regeneration; initial clips

Documents can now supply story/scenes/characters. Source audio uses separately
approved word-timestamp transcription rather than equal-time splits. These
behaviors supersede the corresponding baseline limitations below.

1. Start at the frontend **Studio guide** (`/docs`), the default landing page. Read workflow stages, requirements, limitations and cost philosophy, then configure PostgreSQL and the backend OpenAI key. Review text/image settings in **AI settings**; configure standard speech model/voice and estimate rate in the backend environment.
2. Create a project, review the planning estimate, and explicitly generate the Story Bible. Review/edit the story, characters, and scenes.
3. Explicitly approve the saved story, generate/review character portraits and approve their retained references, then generate scene images after reviewing their estimates. Approve **every scene image**. Changed or regenerated images require approval again.
4. Open **Timeline**. Review the narration estimate and remaining project budget, check approval, and generate narration. Text is based on approved scene titles/descriptions; no provider call happens just by opening the page.
5. Review the narration in each scene. To replace it, approve regeneration; old audio links are invalidated. Review the separate speech estimate, check approval, and generate the missing speech files. Audio is AI-generated with a standard synthetic voice, not voice cloning.
6. Listen to the audio previews. Move scenes up/down and adjust durations; save the timeline. Reordering invalidates narration and story approval: review and regenerate/restore the arc before continuing. Durations must cover the entire narration plus a short tail. Actual audio may extend the planned duration. Saving uses a revision check to prevent overwriting another tab's changes.
7. Open **Render**. Review estimated render cost, runtime, storage, audio duration, video length, model/format information, and cumulative AI estimates. Check explicit approval, then start the render.
8. Watch the current stage, fine-grained percentage bar, completed-scene count, elapsed seconds and approximate time remaining. Progress uses actual encoded media time and stays below 100% until the MP4 is validated and published; ETA can change as encoding speed changes. Refreshing/reopening the page retrieves the persisted job. After a failure or restart, approve **Resume failed render** to reuse validated scene segments. If the timeline changed, start a new render instead.
9. Open **Your video** to play the MP4, review duration/audio/file-size/render-time metrics, and **Download MP4**. Actual provider invoices are unknown, not $0. Local rendering itself has no provider fee, excluding electricity/hardware.

Use **Scenes in this export** to jump to any published scene; each button shows its exact time range.
Local clips move for two seconds, then hold until that scene's narration ends; a long first scene is
not evidence that later scenes are missing. **Play with sound** unmutes the player and starts playback
from a user gesture. If narration remains inaudible, check browser/system volume and the selected
audio output device, or test the downloaded MP4. Final render actions use normal progression-button sizing.
VS Code's embedded browser may not support AAC decoding even though it displays MP4 video.
For these browsers the player automatically uses a locally decoded WAV narration track, synchronized
with play/pause, seeking, playback speed and volume. Downloaded MP4s retain their original AAC audio;
no paid speech or GPU generation is repeated. A notice explains when this compatibility track is active.

## Editing and recovery

- Cards start with titles/artwork only. Expand **details and review** to inspect descriptions/prompts and approve or regenerate; expand timeline controls for narration, audio, duration and ordering. Story editors, guide sections and long explanations also expand on demand. Approval/advance actions are on the right; saving alone never approves content.

- Story/identity/scene-content changes invalidate the whole narration arc and its audio. Regenerate/restore narration/audio and reapprove changed images before rendering.
- Scene image changes reset image approval but do not require new speech if the narration source is unchanged.
- Reordering does not automatically regenerate or charge for narration/audio. It invalidates the connected arc/audio and story approval: review the new order, approve the story, and explicitly regenerate narration/audio (or restore supplied narration locally) before a new render.
- Failed speech attempts retain their estimate reservation; completed files are reused on retry. Show the refreshed estimate before retrying.
- The last successful video stays downloadable while preparing or retrying a replacement. It represents the earlier timeline until a new render succeeds.
- Media and render checkpoints remain under the local project directory. Keep database and media backups together. Never start multiple backend processes against the same database.

## Quality and adaptive-input workflow

- Optionally choose **Start from supplied assets** on New project. Supply a full story, scenes, narration, character definitions, described images, audio, or a mixture. Preview the detected types and missing-asset workflow; correct heuristic text detection before confirming import. Import cannot replace an already planned project.
- Full supplied stories are kept verbatim. Existing scenes/characters/images remain unchanged; only missing bibles/plans are generated. Describe every image; filenames are not treated as visual understanding.
- For audio, review and approve the separate transcription estimate, then review the transcript before missing-asset planning. The original source is retained; normalized audio is used instead of paid synthetic speech. Supplying an explicit narration script with audio avoids transcription. Without supplied scenes, script/audio uses one segment; multi-scene import splits words/time evenly and needs timing review.
- Global project status shows current stage, review counts, incomplete files/narration and required actions. Cancelling a skipped-review dialog makes no paid retry. **Continue Anyway** is an explicit, audited choice, not approval of the content.
- Character approval shows local identity-field/reference coverage. The readiness score combines character/narrative/scene-context coverage, available files and reviews; it does not measure visual similarity or prove story quality.
- Narration is one connected arc with bridges spoken exactly once. Review prior/current/upcoming context and the complete audio; edits to story/identity/scene content/order invalidate the entire arc, not just one summary.
- Timeline motion controls expose slow zoom, pan, simulated parallax and crossfade/black/white/blur transitions. Focus/pacing/instructions are visible. Deferred animation/movement prompts are planning metadata only; character animation never executes.
- Loading messages rotate randomly without repeats until each workflow's catalogue is exhausted. They supplement actual stage/progress and never imply a task completed.
